# 课立方 · 项目约定

本项目是**演示用 demo**，不是上线系统。

## 前端界面规则（硬性）

**风格是「简洁专业 · 双色」：整个界面只有两支颜色。**
一支墨承担全部文字和线条，一支蓝承担主操作和选中态，其余全是中性灰。
落地只有一层：`frontend/src/styles/index.css` —— **页面只引用 token，不自己写视觉**。

> **2026-09-19 起，这一节替换掉了原来的规则。** 原来的规则是「字体统一用宋体、不写任何视觉样式、
> 组件一律用 Element Plus 默认外观」，理由是「评委看的是数据联动，不是界面」。
> 现在这套界面是从姊妹项目 `Calculate-the-cubic-meter-main-2` 整体移植过来的
> （那个项目单独做了五轮 UI 收敛），**不要再按宋体那套改回去**。

| 层 | 文件 | 放什么 |
| --- | --- | --- |
| token | `frontend/src/styles/index.css` 的 `:root` | 颜色 / 字号 / 间距 / 圆角 / 控件高度，外加 Element Plus 变量映射 |
| 页面 | `views/` `layouts/` `components/` | 只引用 token，拼版式 |

**规范和参考件的关系**：配色和字号看本文件第 3 / 6 条；
结构和密度（间距/圆角/阴影上限、斑马行、等宽数字、状态标签）来自
[`数据密集-设计规范.md`](../数据密集-设计规范.md)；
`Apple-HIG-设计规范.md` 只是**参考资料** —— 按它做过一版，处处圆角加阴影加主色，
界面像生成的模板，现在是刻意偏离它的，别照着往回改。

**现行参考件**：[`stylekit.top/zh/styles/data-dense`](https://www.stylekit.top/zh/styles/data-dense)。
它的内容跟 `数据密集-设计规范.md` 同源，但**看它的实际渲染效果比读规范有用**。

**色值原样照抄**（`#3b82f6` / `#ef4444` / `#22c55e` / `#f8fafc` / `#1e293b` / `#64748b` / `#e2e8f0`）——
在姊妹项目里我一开始"改良"成深半档的 `#2563eb`，被用户否掉了，原话「**不要这个深色，改参考件的颜色**」。
**它有两处不要照抄**：一是**字号**（12 / 14px，对中文投屏太激进），二是**深色模式**（它压根没有）。

**八条不能破的：**

1. **不写死色值和字号。** 一律 `var(--color-primary)` / `var(--text-sm)` / `var(--space-3)`。
   写死会让以后改主题直接失效。
2. **只有两支颜色。** 墨（`--label-*` / `--separator`）和蓝（`--color-primary-*`）。
   **不要引入第二支蓝**：`--color-info` 就是指向主色的，不是另一个色值。
   语义色（成功/警告/危险）只用于数据状态编码，都压到 700 号、面积很小 —— 那是第三条轴，不是装饰。
   反例（都改掉过）：每个按钮都带一层淡蓝底、课程卡左侧一条蓝、时间文字用蓝、头像用蓝圈。
   **给分类值上色前先问：这个颜色在说什么？** 说不出就说明是装饰，用中性灰。
3. **主色分"面 / 字 / 面上的字"三个 token，不要混用。**

   | token | 用途 | 值 |
   | --- | --- | --- |
   | `--color-primary` | 当"面"（按钮底、选中块、侧栏选中） | `#3b82f6` |
   | `--color-primary-text` | 当"字"（链接、选中标签页） | `#3b82f6` |
   | `--color-primary-on` | 压在"面"上的字 | `#ffffff` |

   分成三个是因为它们的最优解不一定一致，改其中一个不用动另外两个。

   ⚠️ **已知偏离 AA，是有意保留的**：`#3b82f6` 压白字 3.68:1（主按钮、侧栏选中），
   当字压白底 3.52:1（选中的标签页）。**参考件自己也是这个数**，用户明确要求照抄它。
   要修只需把上面前两行换成 `#2563eb`（5.17:1），一行的事 —— 但**别自作主张改**。

   **语义色分"面 / 字"两套**：`--color-danger`(`#ef4444`) 只当块面，当字用 `--color-danger-text`(`#b91c1c`)。
   直接拿 500 号当字用会不达标（`#ef4444` 压白底 3.76:1、压标签底 4.41:1）——
   参考件规范本身也是这么分的（`bg-blue-50 text-blue-700`）。改语义色时两套一起改。
4. **间距封顶 20px，圆角封顶 6px。** token 里**根本没有** 24 / 32 两档间距，也没有 `--radius-xl`——
   干脆不给这两个值，写不出来就违不了规。要用更大的间距说明版式有问题，不是 token 不够。
5. **卡片用 1px 细线，不用投影。** `--shadow-pop` 只有一档，且只给真正浮起来的层
   （dialog / dropdown / 底部弹层）。卡片一个个浮在灰底上会让整页看起来像模板。
   **不是胶囊**：圆角 `--radius-md`(4px)，`--radius-full` 只给头像、抓手这类本来就是圆的元素。

   **表格不套"卡片里的卡片"**：`.k-card--table` 横向内边距为 0，表格通栏铺到卡片边，
   行分隔线和斑马行一直拉到底；操作条自己补 `padding: 0 var(--space-3)`。
   表格再往里缩一圈，斑马行就断在中间，是最显"模板感"的做法之一。
   **表头不填灰底**：白底 + 一条 `--separator-strong` 下沿线，靠字号和颜色差分层。

   **表格列用 `min-width`，不用 `width`。** 配置项是 `CrudField.minWidth`。
   固定宽度会被 Element Plus 硬裁，字号一调大表头就折行。
   注意 el-table 按各列 min-width 的**比例**分剩余空间，所以主标识列（第一列）要给得比别列大，
   `CrudTable.vue` 里对没写 `minWidth` 的第一列兜底 240px、其余 140px。

   **min-width 是预算，不是各列自己的偏好。** 一列列单独看着都合理，加起来超过内容区宽度
   （1440 屏下约 1186px）就会横向滚动，把「操作」列推出可视区 —— **页面上完全看不出异常**，
   只能量 `.el-table__body-wrapper` 的 `scrollWidth` 才发现。加列或调宽后必须重新算总和。
   （2026-09-19 移植时就是这样漏掉了三处：签到管理、内容托管、基础数据-班级。）
6. **最小字号 14px，正文 17px。** 字号阶是 `14/15/17/21/25/30`，**等比**，档距 1.13～1.24 倍。
   表头、角标用 `--text-2xs`(14px)；次要说明、菜单、表单标签、状态标签用 `--text-xs`(15px)；
   正文、表格、表单、按钮用 `--text-sm`(17px)；区块标题 21px，页面标题 25px，KPI 大数字 30px。

   **这是一套等比级数，不是随手挑的数。** 上一版 `15/16/18/22/26/32` 两头都坏：
   小端三档只差 1～2px（表头、按钮、正文同屏像同一个大小，界面发平），
   大端每档跳 4～6px（正文和 KPI 之间像隔了两级）。**该拉开的地方没拉开、不该拉的拉开了，就是"丑"的主要来源。**
   14 和 15 只差 1px 是有意的：两个都是小字，靠**颜色和字重**分角色而不是靠大小。
   真正撑起层级的是它们跟 **17px 正文**之间那 2～3px 的落差。

   **17px 仍明显大于 Web 常规的 14～16px，不要再往下走。** 历史：字号被用户**连打回三次**
   （`10/12/14` →「字太小了」；`12/13/15` →「字也太小太小了」；`13/14/16` →「**字还是太小太小，放大**」），
   一路抬到 18px；2026-09-19 用户又说整体偏大偏松，**明确要求降到 17px**。
   **13px 及以下一律不用**，别再试探这个下限。
   `数据密集-设计规范.md` 里写的 `text-xs / text-sm`（12 / 14px）对中文投屏太激进，**这一条有意偏离**。
   "数据密集"指的是单位面积里放多少信息，不是把字缩到多小。

   数字、编号、时间、金额一律加 `.k-num`。**`.k-num` 是 `tabular-nums`，不是换等宽字体** ——
   换成 `--font-mono` 会让一行里的数字和中文变成两套字形（字重、x 高、字面宽全不一样），
   像贴了两种字。字号变了记得回头看行高：17px 配上下各 8px 内边距 ≈ 43px 一行。

   **`ch` 是拉丁文单位，中文里不要拿它量宽度。** 一个汉字约等于 2ch，
   `.k-empty__text` 原来写 `max-width: 42ch`，桌面刚好、390px 手机上差一个字符，
   把「继续保持」劈成两行。中文的宽度约束一律用 px（或 em，1em = 1 个字）。
7. **任何文字都要过 WCAG AA（正文 4.5:1）。** 容易被忽略的两处：
   `--label-tertiary` 对白底只有 2.6:1，**只能给占位符和禁用态**，不能拿来写内容
   （"无课"这种也算内容，用 `--label-secondary`）；**语义色当字用要换 `-text` 那一套**（见第 3 条）。
   唯一的例外是参考件的主色蓝，见第 3 条的 ⚠️。
8. **没有深色模式，页面里也不要写 `@media (prefers-color-scheme)`。**
   2026-09-17 用户明确要求去掉（参考件是纯浅色设计，没有深色版）。
   **不要再加回来** —— 真要加，得连参考件的色阶一起重新推一遍，不是补个色值就行。
   减弱动效仍走 `@media (prefers-reduced-motion)`，那个不受影响。

**状态标签**：`components/crud.ts` 的 `CrudField.asTag` 打开就把该列渲染成标签，
配色取选项上的 `tone`（`info` / `success` / `warning` / `danger` / `neutral`），不填即中性灰。
标签颜色也是语义：只在"扫一眼要认出来"的值上用。

**控件高度分两档**，由 `--control-h` 一个变量控制：
桌面 40px，触屏（`max-width: 820px` 或 `pointer: coarse`）抬到 50px。
自己写按钮时用 `height: var(--control-h)`；视觉尺寸想更小就用 `::after` 把可点区补到 `--touch-min`
（例：`views/schedule/index.vue` 的 `.weeknav__btn`）。

**响应式**：表格（包括排课页那张 7 列的周课表）在窄屏**横向滚动，不折叠**——
横过来看跟桌面端是同一张表，不用重新学一遍版式。卡片、KPI 这类才改堆叠。
**占满高度的页面**用 `index.css` 里的 `.k-page--fill`，**不要每页各写一份**：
根元素加 `.k-page--fill` 和 `.k-page`，要吃掉剩余空间的那一块加 `.k-page__fill`，
工具条、数字墙这些固定高度的块不加类（`.k-page--fill` 会定住 `.k-card` / `.k-kpi`）。
现在用在周课表、经营看板、交互课件、电子作业四页 ——
内容只占屏幕一小半、下面空一大片不算"简洁"，算没填满。
⚠️ 两个坑：① 别把定高度的规则写成 `.k-page--fill > *`，周课表要伸缩的那块是 `.week-scroll` 不是卡片，
一刀切会把日历的 `flex: 1` 压掉；② 窄屏**不禁用**这一档（手机端 `.body` 也是定高可滚的），
真正要退回自然高度的是"主从两栏在窄屏堆叠成上下"那种页面，由组件自己覆盖。
`--tabbar-height` 那一套是手机端底部标签栏，学生 / 家长走 `MobileLayout`，其余角色走 `DesktopLayout`
（见 `layouts/AppLayout.vue`）。

**改 Element Plus 外观的姿势**：优先在 `index.css` 里映射 `--el-*` 变量，而不是逐个组件写样式覆盖。
变量够不到才写选择器，并且要注意权重 —— 踩过的坑：

- 没写 `type` 的 `el-button` **没有** `el-button--default` 类，只能反着排除。排除串要包在 `:where()` 里，
  否则那一长串 `:not()` 会把 Element Plus 自己的 hover/focus 规则全压掉。
- 覆盖 `el-radio-button` 选中态时选择器必须带上 `.is-active`，不然压不过 Element Plus 自带的
  `.el-radio-button.is-active .el-radio-button__original-radio:not(:disabled)+...`。
- `--el-button-disabled-*` **和 `--el-button-text-color`** 都定义在 `.el-button--primary` 这一层，
  **写 `:root` 上会被盖掉**。要覆盖得用同等或更高的权重（见 `index.css` 里那几段）。
- 改主按钮文字色时**必须排除 `is-link` / `is-text`**：这两个变体的 `color` 读的就是
  `--el-button-text-color`，不排除的话「编辑」会变成白字，在白底上看不见。
- `.el-table__empty-text` 上写死了 `line-height: 60px` 和 `width: 50%`。
  把 `.k-empty` 塞进 `#empty` 插槽就会整套继承过去 —— 16px 的字撑出 60px 行距、
  再被挤成两行，看起来像空态坏了。`index.css` 里已经把这两个值还原。

**页面结构约定**：页面最外层用 `.k-page`，卡片用 `.k-card`，操作条用 `.k-toolbar`，空态用 `.k-empty`，
数字用 `.k-num`，KPI 数字墙用 `.k-kpi`（**它自己就是卡片，不要再套一层 `.k-card`**；
列数写死 4/2/1 整除，别用 `auto-fit`，否则最后一行会留出露底色的一格）。
**页面标题由布局统一渲染**（取当前路由的菜单名，见 `layouts/DesktopLayout.vue`），
页面里不要再写 `<h2>/<h3>`。

**这一处是有意偏离规范的**（写下来免得下轮又"修正"回去）：

- **表头不做 `uppercase`。** 规范写的是 `text-xs uppercase tracking-wide`，但这是给拉丁字母的；
  中文没有大小写，`uppercase` 是空操作。只取了它的意图：颜色更弱、字距拉开。

**⚠️ 两条被推翻的判断，记下来免得下次又绕回去。**

一是把"AI 味"归因到了**色值**上：说 `#3b82f6` + `#f8fafc` + `#64748b` 是 Tailwind 默认调色板、
大模型生成界面都用它，所以显模板，于是把主色换成了更深的 `#1d4ed8`。
**这个归因是错的。** 用户随后给的参考件用的就是 `#3b82f6`，观感一点不 AI ——
色相不是问题，**处理手法才是**。当时真正的毛病是三条：
表头填了灰底、表格套在卡片内边距里（卡片套卡片）、侧栏选中用淡底。
**下次再听到"AI 味"，先查这三样，不要先动色相。**

二是替用户"改良"了他给的参考件：参考件的 `#3b82f6` 按 AA 算过觉得不达标，
就擅自换成了深半档的 `#2563eb`，结果被要求改回去 —— 他给参考件就是要那个观感，
可访问性该做的是**算出来告诉他**，不是自己动手改掉。

**精力分配始终没变：界面做到"规范、一致、不露怯"即可，不要加动效、插画、自定义组件 ——
那仍然是从业务功能上抢时间。**

## 角色与权限

角色策略**只写一处**：`frontend/src/router/menus.ts`。菜单可见性用 `MenuItem.roles`，
动作权限用导出的 `canEditSchedule(role)` 之类的小函数。页面里不要再各自硬编码角色数组。
手机端底部标签栏的短名用 `MenuItem.short`。

**前端隐藏只是界面收敛，不是权限边界。** 后端 `LoginInterceptor` 只校验"登录了没有"，
不看角色，所以被隐藏的接口任何登录用户都能直接调。改课表这类写操作只在 UI 层挡住，
演示够用；哪天真要拦住，得在对应的 Controller 上加角色校验，光藏按钮是自欺。

当前只有一条动作权限：**课表人人可看，改课表（智能排课 / 清空 / 调课）只有校长和教务**。

## 其他约定

- 严格按 `编码计划书.md` 的目录结构和技术选型执行，不要自行引入计划书里没有的依赖。
  **界面这一项例外**：这套风格的落地全部用 CSS 变量 + Element Plus 原生能力实现，没有引入任何 UI 库。
- **范围原则（2026-09-17 起）**：最小可行 demo —— 基本功能能真实演示即可，不追求高精尖算法或复杂技术。事务一致性、防重复核销、后端角色过滤这类"演示时会被戳穿"的底线必须保；分档薪酬、导出、性能优化等一律不做。
- **本项目没有 `.env`**（2026-09-16 起）：数据库是 H2 内存库、上传目录写死在 `application.yml`、前端 API 前缀写死在 `request.ts`，没有需要按环境改的值，四个 `.env` / `.env.example` 已全部删除。**新增配置项前先问「换台机器跑，这个值要不要改」**，不会变就写死，别再引入 `.env`。
- 不做多租户、不做 Spring Security、不做审计日志、不做 Flyway —— 理由见计划书第一节。
