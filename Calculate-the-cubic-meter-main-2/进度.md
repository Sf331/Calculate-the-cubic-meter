## 界面：简洁专业 · 双色（2026-09-17）

界面方向前后改了五轮，记下来免得再绕回去。

**第一轮**：推翻原来的"统一宋体、不做视觉设计"规则，改按 `Apple-HIG-设计规范.md` 全面落地
（系统字体、44px 控件、卡片 + 圆角 + 轻阴影、胶囊按钮）。
**第二轮**：做完一看，处处圆角加阴影加主色，反而更像 AI 生成的模板 —— 收敛成**密集工具化**。
**第三轮**：按 `数据密集-设计规范.md`（即 `plan.md`）执行，从"少装饰"进一步走到"数据优先"——
间距封顶 20px、圆角封顶 6px、表格斑马行、状态色编码、数字走等宽字体。
**第四轮**：字太小 + "一股 AI 味"，改走**简洁专业 + 双色**。全站只保留"墨 + 一支蓝"，
字号从 `10/12/14/16/18` 抬到 `12/13/15/17/20`。
**第五轮（现行）**：用户拿 `stylekit.top/zh/styles/data-dense` 当参考件，说"太丑太丑了"，
随后连提三条：**推翻第四轮对"AI 味"的归因**、**色值直接照抄参考件**、**去掉深色模式**，
并在过程中第三次说字太小（「字还是太小太小，放大」）。详见下节。

所以现在：**配色和字号看本文档**；结构和密度（间距/圆角/阴影上限、斑马行、等宽数字、状态标签）
仍然沿用 `数据密集-设计规范.md`；`Apple-HIG-设计规范.md` 只是**参考资料**。
可执行的细则在 `.claude/CLAUDE.md`。

怎么落地的 —— **没有引入任何 UI 库，也没有引入 Tailwind**，全部靠 CSS 变量 + Element Plus 原生能力：

| 层 | 位置 | 说明 |
| --- | --- | --- |
| token | `src/styles/index.css` 的 `:root` | 颜色 / 字号 / 间距 / 圆角 / 控件高度，外加 `--el-*` 变量映射 |
| 布局 | `src/layouts/` | 桌面端侧栏 + 工具栏；手机端导航栏 + 底部标签栏 + 更多弹层 |
| 页面 | `src/views/` `src/components/` | 只引用 token |

**关键机制**：`--el-*` 全部指向上面的 token，页面只认 token、不认色值。
自定义属性在使用时才求值，所以改 token 就是改全站 —— 第五轮删掉整个深色模式块，
页面和布局**一行都没改**，就是这个机制在起作用。

### 第五轮改了什么（现行）

#### 先纠正第四轮的归因错误

第四轮把"AI 味"归因到**色值**上：说 `#3b82f6` + `#f8fafc` + `#64748b` 正好是 Tailwind
默认的蓝和 slate、大模型生成的界面清一色是这一套，所以显模板。**这个归因是错的。**

用户给的参考件 `https://www.stylekit.top/zh/styles/data-dense` 用的就是 `#3b82f6`，观感一点不 AI。
色相不是问题。真正的问题是**处理手法** —— 参考件和第四轮实现有三处硬差别：

| | 参考件 | 第四轮实现 |
| --- | --- | --- |
| 表头 | **白底**，只靠一条线 + 字号/颜色差跟数据行分层 | 填了 `--bg-subtle` 灰底 |
| 表格 | 通栏铺到容器边，行分隔线一直拉到底 | 套在卡片内边距里，斑马行断在中间 |
| 侧栏选中 | **实心主色块 + 白字** | 主色淡底 + 主色文字 |

灰底表头 + 卡片套卡片 + 淡底选中，这三样凑在一起就是"模板感"的来源，换多少次色相都救不回来。

#### 色值直接照抄参考件，不再自己"改良"

一开始我把主色定成 `#2563eb`（比参考件深半档），理由是参考件的 `#3b82f6` 压白字只有 3.68:1。
用户否掉了：**「不要这个深色，改参考件的颜色」**。现在色值原样照搬：

| token | 值 | 来源 |
| --- | --- | --- |
| `--color-primary` | `#3b82f6` | 参考件 Accent 1 |
| `--color-danger` | `#ef4444` | 参考件 Accent 2 |
| `--color-success` | `#22c55e` | 参考件 Accent 3 |
| `--bg-canvas` | `#f8fafc` | 参考件「背景辅色」 |
| `--label-primary` | `#1e293b` | 参考件「正文主色」 |
| `--label-secondary` | `#64748b` | 参考件「正文辅色」 |
| `--label-tertiary` | `#94a3b8` | 参考件「正文弱化色」 |
| `--separator` | `#e2e8f0` | 参考件「分隔线」 |

⚠️ **已知偏离 AA，是刻意保留的**：`#3b82f6` 压白字 3.68:1（主按钮、侧栏选中），
当字压白底 3.52:1（选中的标签页）。参考件自己也是这个数。
要改回去只需把 `--color-primary` 和 `--color-primary-text` 换成 `#2563eb`（5.17:1），一行的事。

新增一组 `--color-*-text`（`#b91c1c` 等 700 号），给"语义色当字用"的场合 ——
直接拿 500 号当字用会不达标（`#ef4444` 压白底 3.76:1、压标签底 4.41:1）。
参考件规范本身也是这么分的（状态标签写 `bg-blue-50 text-blue-700`）。

#### 去掉深色模式

参考件是纯浅色设计，没有深色版，用户明确要求跟着它走。
删掉的是 `index.css` 里整个 `@media (prefers-color-scheme: dark)` token 换挡块 ——
**只动了这一处，页面和布局一行都没改**，因为颜色全部经由 token 取值。
验证方式：CDP 里模拟 `prefers-color-scheme: dark` 截图，页面底仍是 `#f8fafc`。

#### 字号：被打回三次，最后一次一步跨到位

| 试过 | 用户反馈 |
| --- | --- |
| `10/12/14`（照搬规范） | 「字太小了」 |
| `12/13/15` | 「字也太小太小了」 |
| `13/14/16`（正文 16px = 浏览器默认值） | 「字还是太小太小，放大」 |
| **`15/16/18/22/26/32`（现行）** | —— |

**教训：不要一档一档地试探。** 16px 对普通 Web 已经不小了，这个用户还是嫌小
（多半是大屏投屏看），所以现在正文直接 18px，**明显大于 Web 常规**，这是有意的。
参考件规范写的 `text-xs / text-sm`（12 / 14px）**有意偏离**。
「数据密集」指的是单位面积放多少信息，不是把字缩到多小。

| 改什么 | 第四轮 → 第五轮 |
| --- | --- |
| 主色 | `#1d4ed8` → **`#3b82f6`**（参考件原值） |
| 字号阶 | `12/13/15/17/20` → **`15/16/18/22/26/32`** |
| 控件高 | 桌面 32 → **40**；触屏 44 → **50** |
| 表头底色 | `--bg-subtle` 灰底 → **白底**，下沿换 `--separator-strong` |
| 表格卡片 | 四周 12px 内边距 → **横向 0**，表格通栏；操作条自己补回内边距 |
| 表格单元格 | 上下 8px、左右 8px → **上下 12px、左右 12px** |
| 侧栏选中 | 淡底 + 主色字 → **实心主色块 + `--color-primary-on`** |

| 侧栏 / 顶栏 | 184px / 44px → **220px / 54px** |

**表格列宽从 `width` 改成 `min-width`**（`CrudField.minWidth`）。
用固定宽度时 Element Plus 会硬裁，字号一调大表头就折行 ——「单次时长(分)」被挤成两行、
「课程名称」被挤成"初一数学 / 提高班"两行，都是这么来的。
`min-width` 下列自己会撑开，以后再调字号不用回来改一遍。
注意 el-table 是按各列 min-width 的**比例**分配剩余空间的，所以第一列（主标识列）
必须给得比别的列大，`CrudTable.vue` 里对没写 `minWidth` 的第一列兜底 240px。

#### 仍然成立的两条（沿用第四轮）

**双色怎么定义**：一支墨承担全部文字和线条，一支蓝承担主操作和选中态。语义色（成功/警告/危险）
是第三条轴，只用于数据状态编码，且都压到 700 号、面积很小 —— 扫一眼仍然是双色的观感。
`--color-info` 直接指向主色（`var(--color-primary)`），全站不允许出现第二支蓝。

**主色必须拆成三个 token**，这是第四轮最值得记的一条：

| token | 用途 | 值 |
| --- | --- | --- |
| `--color-primary` | 当"面"用（按钮底、选中块、侧栏选中） | `#3b82f6` |
| `--color-primary-text` | 当"字"用（链接、选中标签页） | `#3b82f6` |
| `--color-primary-on` | 压在"面"上的字 | `#ffffff` |

起因是对比度审计抓到深色主按钮**白字压在亮色上只有 2.98:1**，深色选中菜单 3.7:1，都不达 AA。
当时"面"要亮才跳得出来、但"字"压在面上反而要转深墨，两者最优解相反，共用一个变量必然有一头翻车。
**现在没有深色模式了，三个 token 的取值恰好一致 —— 但拆分留着**，因为改其中一个不用动另外两个，
而且哪天要加回深色，这个结构是现成的。

**语义色同样拆两套**（第五轮新增）：`--color-danger`(`#ef4444`) 只当块面，
当字用 `--color-danger-text`(`#b91c1c`)；success / warning 同理。
直接拿 500 号当字用会不达标 —— `#ef4444` 压白底 3.76:1、压标签底 4.41:1，
换成 700 号后 `#b91c1c` 是 6.47:1 / 5.91:1，同时也更贴参考件规范（它写的是 `text-red-700`）。

**其他（跨轮累积）**：

- **周课表撑满视口高度**。之前日历只占屏幕三分之一、下面空一大片，不像"简洁"像没做完。
  做法是让 `.k-page` 变成 `height: 100%` 的 flex 列，操作条 `flex: none`，`.week-scroll` 吃掉剩余空间并横向滚动
- **状态标签**机制不变（`CrudField.asTag` + 选项上的 `tone`），目前只在「课程 → 课型标记」上开
  （试听=蓝、补课/代课=琥珀、跨校区=灰）
- **禁用按钮**：Element Plus 默认给主按钮套淡色底 + 白字，统一压成灰底灰字
- **`无课`从 `--label-tertiary` 改成 `--label-secondary`** —— 它是内容不是装饰，前者对白底只有 2.56:1
- 登录卡片 440px、导航项 38px 一行（字号抬到 18px 后跟着放大的一批尺寸）

**对比度审计**：写了个 CDP 脚本，读运行时真实渲染出来的文字色和背景色
（背景要往上找第一个不透明祖先，并把半透明层合成掉），算 WCAG 对比度。
排课页 + 课程表两页跑下来，**共 5 项不达标，全部是同一个色对**：

| 位置 | 字号 | 实测 | 要求 |
| --- | --- | --- | --- |
| 侧栏选中（白字压主色块） | 18px | 3.68 | 4.5 |
| 主按钮（白字压主色块） | 18px | 3.68 | 4.5 |
| 选中的标签页（主色字压白底） | 18px | 3.52 | 4.5 |

**根因是参考件的主色 `#3b82f6` 本身**：它压白字 3.68:1、当字压白底 3.52:1，
参考件自己的主按钮也过不了。这不是改坏的，是**照抄参考件的已知代价**，用户明确要求照抄。
修法只需把 `--color-primary` 和 `--color-primary-text` 换成 `#2563eb`（5.17:1），一行的事，
**但不要自作主张改** —— 先问。

其余全部达标：表头 15px 4.76、表格数据 18px 14.63、提示标签 15px 6.16、
危险按钮 16px 6.47、次要说明 16px 4.76、未选中标签页 18px 4.55。
五种状态标签的配色单独算过（课程表只渲染得出一部分），4.79–6.92:1。

**踩过的四个 Element Plus 权重坑**（已写进 `.claude/CLAUDE.md`，别再踩）：
没写 `type` 的 `el-button` 没有 `el-button--default` 类；覆盖 `el-radio-button` 选中态必须带上 `.is-active`；
`--el-button-disabled-*` 和 `--el-button-text-color` 都定义在 `.el-button--primary` 那一层，写 `:root` 上会被盖掉。
其中 `--el-button-text-color` 还有个连带坑：`is-link` / `is-text` 变体的 `color` 读的就是这个变量，
改主按钮文字色时必须把这两个变体排除掉，否则「编辑」会变成白字，在白底上看不见。

## 课表的角色收敛（2026-09-16）

`/schedule` 的 `roles: []` 意味着人人可见，之前教师/学生/家长登录后也能看到「智能排课」「清空课表」，
点课程卡还会弹出调课窗。现在按角色分开：

- **课表内容人人可看**，`canEditSchedule(role)` 决定能不能改，策略写在 `router/menus.ts`（和菜单同一处）。
- 只读角色的**课程卡渲染成 `div` 而不是 `button`**（用 `<component :is>` 切换）。
  只藏按钮是不够的 —— 课程卡本身就是调课入口，留着 `button` 等于绕过去了。

**⚠️ 但这只是界面收敛，不是权限边界。** 实测（后端跑在 18080）：

```
# 以 student01 登录后，直接打接口
POST   /api/schedule/generate   → {"code":0,"data":{"placedCount":10,...}}   # 排课成功
DELETE /api/schedule            → {"code":0}                                  # 课表被清空，40 节 → 0 节
```

`LoginInterceptor` 只判断 session 里有没有用户，**不看角色**。要让上面两条真的被拒，
得在 `ScheduleController` 的写接口上加角色校验（读接口不用动）。演示时如果不会用学生账号
去调接口，可以先不做，但别以为现在这样就是安全的。

## 重要约定（别推翻）

### 数据与配置

- 数据库：**H2 内存库**（`jdbc:h2:mem:kelifang;MODE=MySQL`），不需要装任何数据库
- **没有 `.env`**。四个 `.env` / `.env.example` 已全部删除：上传目录写死在 `application.yml` 的 `kelifang.storage-path`，前端 API 前缀写死在 `request.ts` 的 `baseURL: '/api'`。**新增配置项前先问「这个值真的会变吗」，不会变就写死，别再引入 `.env`**
- **每次重启后端，整库重建**。`schema.sql` 每张表都是 `DROP TABLE IF EXISTS` 打头，`spring.sql.init.mode=always`。改表结构直接重启即可，不用手工清库；但**演示数据不会累积**
- **H2 索引名是全库唯一的**（MySQL 是表级唯一），所以 schema.sql 里重名的索引都带了表名前缀，例如 `idx_teacher_user_id`。新增索引时注意别撞名
- **JSON 列在 H2 里写成 `TEXT`**。MySQL 的 `JSON` 列 `getString()` 返回原始 JSON 文本，H2 的 `JSON` 类型返回的是二次编码的字符串，会让 `JacksonTypeHandler` 解析失败

### 代码模式

- **新增基础数据实体照抄四件套**：`entity` + `mapper` + `service`（`extends ServiceImpl`，只需实现 `check()`）+ `controller`（`extends BaseCrudController`，18 行）。实体加 `implements IdEntity`，Lombok 会自动满足接口
- **前端新 CRUD 页面**：写一段 `CrudField[]` 配置 + 塞进 `CrudTable`，不用写表格代码
- **业务校验写在 Service 的 `check()` 里**，Controller 是信任边界，但规则归 Service
- **模块之间不直接查对方的 Mapper**，走对方的 Service（例：`basedata` 要家长账号，加的是 `AuthService.listByRole()`）

### 排课引擎（最容易改错的地方）

- **没有优化阶段，也别去加。** 只有贪心构造，不存在局部搜索/模拟退火/目标函数。计划书里曾写过 `LocalSearchOptimizer` 和 `score = 5×…-2×…-1×…`，那是纸面设计，代码从来没实现，2026-09-16 已从计划书删除。**能排出合法课表就是验收标准**
- **调课校验必须复用 `ConstraintValidator`**，不要另写一套。`ScheduleService.move()` 和 `IncrementalRescheduler` 都走它。另写一套必然出现"自动排的合法、手动挪的非法"
- `IncrementalRescheduler.resolve()` 里对目标时段要做**两次**校验：
  1. 第一次传**空占用集** —— 只查结构性约束（教学网格、教师/学生可用时段、容量、资质）。这些挪开别人也解决不了
  2. 第二次才查占用冲突 —— 这些可以靠挪开别人解决
  **漏掉第一次会让引擎对 08:00 这种非法时段报"可行"**（已修过一次，别再踩）
- 候选时段排序用**负载优先**（`validator.loadOn(date)`），不是"周一到周日"。改回后者课表会全挤在周一周二
- 教师/学生**没配可用时段 = 不受限**。故意如此，否则没配约束数据时一节都排不出来
- 教学时段网格写死在 `TeachingGrid` 常量里（工作日 16:00–21:00，周末 09:00–21:00，30 分钟粒度）
